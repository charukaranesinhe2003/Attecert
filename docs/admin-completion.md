# Administration improvements — completion report

15 October 2026. Read [the investigation and prioritized findings](admin-review.md) for the architecture, workflow trace, initial file evidence, page proposals, impacts and dependencies. That investigation was recorded before implementation. This report records the first implementation phase. **The [follow-up report](admin-followup.md) supersedes the remaining items, migration status, localization status and test totals below**, including the now-implemented password, transition, validation and durable-mail work.

## System and workflows

AtteCert is a PHP 8.2/MySQL application with public pages, an authenticated customer portal and a staff console, server-rendered from PHP views. Its central case connects customer, destination, services, quotation snapshots, invoices, payment/refund ledger, MOFA/embassy snapshots, files and status history. The custom kernel/router/container supply sessions, CSRF, validation and role/permission middleware. PHPMailer and mPDF handle mail and PDF documents.

Traced paths were registration/optional verification/login/password recovery; public enquiry and automatic customer/case creation; staff case review and quotation preparation/revision; customer acceptance/rejection and invoice conversion; payments/refunds/cancellation; processing updates and completion; document ownership/visibility/download; contact/support triage; notifications/mail recovery; reporting/export; catalog/content/translation/staff/settings administration. There are no tutor, student, booking, assessment, gateway or commission modules to redesign.

## Routes, data and compatibility

Existing routes remain in use. The added POST `/admin/documents/{id}/visibility` requires `documents.upload`, CSRF and explicit confirmation; it only changes the existing `documents.customer_visible` flag. Archive also requires explicit confirmation. List filters extend existing GET routes: case status=active/unquoted; invoice status=unpaid/overdue; document category/visibility/case_id/search; current process status=active. Dashboard and search responses omit inaccessible groups rather than fetching then hiding them.

Writes affect existing users/user_roles/customers, case_services, quotations/items/versions, invoices/items, payments, process snapshots, documents, notifications, email_logs and audit_logs. Catalog writes use existing service/country/translation/pivot/FAQ/article tables. Historical commercial records and processing snapshots remain intact. There is no schema migration to apply.

## Verification

The original suite passed before edits: 1 test, 4 assertions. Focused integration tests now use randomly named disposable MySQL databases, real migrations/seed data, isolated storage and disabled SMTP. Per-test transactions roll back ordinary fixtures; concurrency tests use guarded worker processes and remove their disposable database afterward. The configured application database was inspected read-only. The original mutation-heavy cli/flow.php was not run against it.

The suite covers real intake → customer/case → quotation → customer acceptance → invoice → payment → private document → explicit release → authorized download → completion/tracking; customer ownership denial; staff permissions; role escalation/lockout; customer suspension and legacy active-flag mismatch; payment/refund bounds; cancellation; quotation revision isolation; invoice idempotency; impossible dates; latest-snapshot queues; KPI/list agreement; catalog preservation/duplicates; PDF generation; mail attachment reconstruction; invalid report ranges/export; document visibility/audit/notification behavior.

Two real two-process race tests verify competing payments (only one 60-of-100 payment accepted and invoice balance equals ledger) and simultaneous invoice creation (both requests return the same invoice with one complete item set).

Browser checks on the disposable fixture verified login, desktop and narrow layouts, mobile menu open/close and grouped links, live search suggestions under CSP, accurate completed-file queue, explicit release confirmation, actual POST/CSRF release and resulting empty queue with honest SMTP-unconfigured feedback, and report labels/empty states. Browser console checks returned no errors. Tests did not send real email, make external payments or change existing accounts.

Final execution: **47 tests passed, 289 assertions**, in 20.932 seconds on PHP 8.2.12/MySQL 8.0.42. PHP lint passed for **190 source files**; both public.js and admin.js passed `node --check`; `git diff --check` passed. Early regression runs exposed incorrect column names in two newly written test assertions; those assertions were corrected to the actual schema and the complete final suite passed. The tests did not require changing the database schema.

The temporary preview was stopped and its disposable database/storage removed after browser QA. A final read-only check confirmed all 11 inspected application table counts match the pre-change baseline. No generated test databases remained.

## Remaining issues and ordered next steps

1. **High — agree the staff credential workflow.** must_change_password remains unenforced and staff lack a dedicated credential-change page. Implement and test a forced-change route/access policy after agreeing behavior; the current flag alone does not enforce anything.
2. **High — establish allowed automated/manual status transitions.** The existing model permits manual transitions and payment/quotation events can move a case backward. NextStep also assumes embassy after MOFA and may suggest processing for later paid cases. The existing user-edited helper was preserved. Do not introduce a mandatory processing pipeline without requirements for translation/apostille/other case types.
3. **Medium — complete configuration and quotation-input validation.** Settings still accept some invalid durations/URLs/currency values; quotation numeric inputs need stronger domain constraints. These require explicit accepted ranges and rules, rather than silent business-rule changes.
4. **Medium — communication reliability.** Real SMTP delivery was not exercised. Mail is still attempted inside some database transactions; a durable outbox and retry policy would be a separate architectural change. Resends regenerate the linked current immutable commercial document; no arbitrary historical attachment metadata was migrated.
5. **Medium — broaden operational filters/history/privacy.** Contact/search/export surfaces beyond the touched pages and unrestricted list sizes can be improved as volume grows. Public visible timeline includes staff names and deserves a deliberate privacy decision. Invoice/quotation missing-record handling remains inconsistent in some untouched paths.
6. **Low — localization and accessibility review.** New labels rely partly on English fallback; obtain Sinhala/Tamil copy review. Browser checks are not a formal accessibility audit or exhaustive device/browser matrix.
7. **Low — operational deployment checks.** Confirm the external daily cron for quotation expiry/overdue invoices, production role assignments, backup procedures and SMTP configuration in the intended deployment. No deployment or environment overwrite was performed here.

No claims are made that these remaining workflows, production configuration or real external delivery have been completed. The initial finding table distinguishes delivered fixes above from these follow-ups.
