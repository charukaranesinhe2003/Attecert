# AtteCert project and administration review

Review date: 15 October 2026. Initial investigation completed before implementation.

## Project map and evidence

AtteCert is a PHP 8.2 server-rendered MySQL application, not a learning or booking platform. `public/index.php` boots the container and kernel; `routes/web.php` declares public, authenticated customer and permission-guarded staff routes. Controllers validate requests, services execute prepared SQL through `app/Core/Database.php`, and PHP views render responses. There is no SPA, separate API server or ORM. JavaScript enhances forms, search, tabs and navigation. Composer supplies PHPMailer, mPDF and PHPUnit.

The schema is in `database/migrations/001_schema.sql` and `002_contact_accounts.sql`. A customer optionally links to a login user. A case links customer, country, document type, assigned staff, services and status history; quotations and invoices snapshot their items and prices; payments link invoices, customers and cases. Documents link cases or enquiries. MOFA/embassy rows are append-only process snapshots. Notifications belong to login users. Contact/support messages, email logs and audit logs support administration. Catalog/content/translation tables supply the public website.

Roles seeded in `database/seeders/DatabaseSeeder.php` are super_admin, admin, manager, processing_staff, finance_staff, customer_support, content_editor and customer. Permissions are database-backed; super_admin has an explicit bypass. Each non-customer role is staff. Role middleware and module permissions exist, but some overview and contextual screens bypass module boundaries (findings below).

Read-only inspection of the configured local database found 19 users, 15 customers, 16 cases, 12 quotations, 9 invoices, 8 payments, 16 documents, 9 quote requests, 6 contact messages, 74 audit entries and 20 email logs. No personal values or credentials are included here. These are local sample counts, not production claims.

## Traced workflows

| Workflow | Initiator, transitions and responsible role | Records, feedback and exceptions |
| --- | --- | --- |
| Registration/login/recovery | Customer registers; optional email verification; active verified login; hashed expiring reset token | AuthController/AuthService create users, customer role and customers in a transaction. Login checks active state, credentials, verification and attempt limits. Staff verification is exempt. must_change_password is recorded but unenforced. |
| Enquiry to case | Public/customer POST /quote; staff reviews linked case and selected services | QuoteController → IntakeService stores quote_requests/services/uploads, creates or links customer/account/case, acknowledgement and tracking notification. Guest contact and signed-in support use contact_messages; no conversation/reply module exists. |
| Quotation | Staff prepares draft or issues; customer views, accepts or rejects; revisions retain historical prices | CaseController → QuotationService calculates catalog fixed/custom prices, quotation_items and audit. Customer controller verifies ownership. Acceptance creates invoice and moves case; rejection records reason. Revision isolation and state/concurrency defects are verified below. |
| Invoice/payment/refund | Finance staff creates/sends invoice; manually records payment or refund; full settlement updates case | InvoiceService/PaymentService update invoices, invoice_items, payments, notifications, mail and audit. Bounds prevent ordinary overpayment/refund, but pre-lock validation races. Cancellation requires no paid balance and a reason. No gateway, commission or dispute subsystem exists. |
| Processing/completion | Authorized staff updates MOFA/embassy snapshots, optionally synchronizes case, uploads final files, completes case | ProcessController, WorkflowService, DocumentService. Process history is retained. Status model permits manual transitions rather than a mandatory pipeline. Translation/apostille cases must not be forced through embassy stages. |
| Documents/tracking | Staff uploads and elects visibility; owner downloads; public tracks case number | MIME/size checks, random stored names, ownership/visibility checks and download/audit records exist. Public tracking omits contact/financial/file records; visible timeline still warrants privacy review. Existing private files lack release control. |
| Operations/reports | Staff searches, reviews queues, filters lists, exports and resends failed mail | ReportService queries real data. Daily cli/cron.php expires sent/viewed quotes and marks invoices overdue; external scheduling is required. Mail honestly records sent/logged/failed, with SMTP-unconfigured messages persisted locally. Resend currently loses attachments. |
| Website/admin configuration | Authorized content staff manages catalog/content/translations; admins manage staff/settings/audit | Existing forms and per-route permissions exist. Some forms omit fields they overwrite. No in-app backup, tutor, student, booking, assessment or moderation module is present. |

## Prioritized findings (initial baseline)

All entries marked verified were traced through their implementation. Recommendations are not claims of runtime failure. File references below describe the baseline before edits.

| ID / category | Priority / certainty | Problem and evidence | Impact; recommended solution; dependencies |
| --- | --- | --- | --- |
| SEC-1 Security/permissions | High · verified | Staff-only /admin and /admin/search load all records: routes/web.php:109–110; ReportService::dashboard/attention; SearchController::find | Content editor can retrieve customer and finance information. Scope queries, cards, tasks and destination links by existing module permissions. Depends on AuthService::can. |
| SEC-2 Security/permissions | High · verified | UserController::update lacks creation's super-admin guard and accepts customer targets/roles | Privilege escalation and unauthorized disabling of privileged accounts. Validate staff role/target before writes, share privileged-role policy, transact and audit. Preserve multi-role records unless an explicit change is requested. |
| FIN-1 Data integrity | High · verified | PaymentService::record reads invoice before transaction; InvoiceService::cancel reads and writes without locking | Concurrent payment/refund/cancel can lose balances or exceed limits. Lock invoice and validate/update/audit within the transaction. No schema change needed. |
| FIN-2 Critical functional error | High · verified | QuotationService::save fallback revision lookup omits case_id | Submitted foreign quotation_id can supersede unrelated customer's quotation. Resolve/lock same-case parent before any writes, reject invalid IDs. |
| WF-1 Broken workflow | High · verified | cases/show.php posts quotation_id only for draft, although issued UI says Create revision | Revision becomes unrelated v1; old quotation remains acceptable. Submit correct source ID, hydrate saved items/totals/terms, preserve issued snapshots. Depends on FIN-2. |
| WF-2 Broken workflow | High · verified | invoices/show.php and cases/show.php hide payment form for paid invoices | Supported full-payment refund cannot be performed. Expose bounded refund action using existing payments.create permission and backend checks. Depends on FIN-1. |
| WF-3 Broken workflow | High · verified | CustomerController::update defaults missing is_active to 1; checkbox submits nothing when unchecked | Admin cannot suspend customer/login. Treat missing checkbox as false, update both records atomically, enforce customers.edit in UI. |
| UX-1 Poor usability/data | Medium · verified | Dashboard active link uses nonexistent status=active; awaiting-payment total covers four statuses but links only sent; quotation count includes cases absent from destination | KPI drilldowns disagree with counts. Share filters/definitions and split drafts from unquoted cases; expose matching records and scope descriptions. |
| PROC-1 Inefficient process | Medium · verified | ReportService attention and ProcessController queues query all historic process rows; workspace reads latest snapshot | Completed work remains pending and duplicates tasks. Select latest snapshot per case, retain history, prioritize due work. |
| PROC-2 Incomplete workflow | Medium · verified | Dashboard Release document links to existing files with no visibility mutation | Private completed files are stuck. Add an explicit confirmed visibility action, existing upload permission, audit and existing notification behavior; never release automatically. |
| FIN-3 Data consistency | Medium · verified | Dashboard revenue ignores negative refunded entries; reports include them; currencies are summed | Inconsistent financial figures. Label receipts/refunds/net explicitly and avoid presenting mixed-currency totals as one currency. Currency policy needs a product decision if mixed data exists. |
| ERR-1 Error/edge handling | Medium · verified | CSP script-src self blocks inline AtteCertAdmin configuration; live search silently ignores failures; public.js/admin.js both bind confirmation | Search unavailable under policy, stale responses and hidden errors; duplicate destructive confirmations. Move config to HTML data attributes, cancel stale requests and show failure state, use one confirm handler. |
| FIN-4 Performance/maintainability | Medium · verified | InvoiceService::createFromQuotation is not atomic/locked; CaseService::syncServices replaces rows outside transaction | Repeated concurrent requests can duplicate invoices, failed copies leave partial records. Lock parent quotation and transact; validate and transact service replacement. |
| FORM-1 Incorrect data | Medium · verified | Service form omits category/SEO fields that controller writes; country omits SEO; article omits featured; country/FAQ active is always checked | Ordinary saves erase metadata or reactivate records. Represent/preserve stored values, retain failed input and use field validation. Catalog multi-table writes also need atomicity and duplicate handling. |
| AUTH-1 Broken workflow | Medium · verified | must_change_password set but never enforced; no staff password-change page | Temporary-password flag gives false assurance. Dedicated staff credential flow/enforcement requires agreement on routing and access before implementation. |
| MAIL-1 Incomplete recovery | Medium · verified | MailService::resend uses persisted HTML, no original PDF attachment metadata | Retried quotation/invoice mail loses PDF. Reconstruct attachments from linked entity or persist safe metadata; review resend permissions/audit. |
| CFG-1 Error/edge handling | Medium · verified | Report date strings/order unvalidated; SettingsController accepts arbitrary durations, upload sizes, URLs/currency | Invalid queries/configuration and confusing errors. Strict dates and ranges; allowlisted setting validators preserving values. |
| UX-2 Poor usability | Medium · verified | Flat 22-item sidebar; responsive table CSS expects data-label absent from many lists; long list pagination controls | Harder discovery and mobile reading. Group existing responsibilities, label cells and use bounded pagination. No new modules required. |
| LOG-1 Accountability | Low · verified | Process changes without status sync, contact status and mail resend lack explicit audit events | Sensitive/recovery operations harder to trace. Audit confirmed changes in existing audit_logs, validate target records. |
| RULE-1 Optional enhancement | Low · recommendation | WorkflowService permits all manual transitions; NextStep assumes embassy after MOFA and paid state can obscure later steps | Requirements needed for mandatory transitions/processing eligibility. Do not add automatic decisions or a new transition matrix. Preserve user's existing NextStep edits. |

## Proposed admin experience

The overview should contain a few permission-scoped current backlog KPIs, prioritized actionable records with matching drilldowns, limited recent cases and links appropriate to each staff role. State clearly that these are current queues; date-range analysis belongs in Reports. Keep detailed finance/history/content forms off the overview.

| Page/group | Purpose and information | Actions, filters and connections | Permissions/edge cases |
| --- | --- | --- | --- |
| Overview | Current active cases, draft quotes/unquoted cases, unpaid invoices, private completed documents | Accurate list links; urgent/oldest tasks; direct record workspace links; small recent-case list | Query only authorized modules; restricted content-only staff get useful website links and no operational data |
| Operations: cases | Case hub: customer, services, history, quote, finance, processing, documents | Search number/customer/document; status/country; contextual tabs; assignment/status/upload | Existing cases.* and module action permissions; terminal/deleted records and validation failures |
| Operations: enquiries/support | Quote request/contact/support triage | Search/source/status; review and convert existing request, mark contacted/closed/spam; links to customer/case | quotes.manage, cases.create for conversion; no invented messaging module |
| Operations: customers | Contact and account overview, linked cases | Search and pagination, edit contact/active, contextual cases | customers.view/edit; synchronize login suspension; avoid editing staff via customer endpoint |
| Operations: processing/documents | Latest MOFA/embassy snapshots, due dates, category/visibility/files | Current queues with case links; explicit process updates; search/case/category/visibility, download/release/archive | cases.edit, documents.download/upload/delete separately; retain history and require explicit release |
| Finance: quotations/invoices/payments | Issuance/decisions, balances, dated ledger/receipts | Search/status, draft revision, send/retry, customer decision, payment/refund/cancel with reasons | Existing quotation/invoice/payment permissions; bounds, ownership, stale requests and cancellation races |
| Reports | Defined date ranges, case/service/country distributions, receipts/refunds and outstanding | Date validation, meaningful empty states and accurate CSV/PDF export | reports.view; creation vs completion vs payment dates explicitly distinguished; multi-currency policy unresolved |
| Website | Existing services, countries, articles, FAQs, document types, content and translations | Edit complete fields, publishing/active, search as volume requires | Existing manage permissions; preserve metadata and unpublished state |
| Administration | Staff roles/active state, email recovery, audit, settings | Validated account changes, audit review, truthful send status and resend | users.manage, audit.view, settings.manage and existing email permission; protected super-admin changes |

## Implementation boundaries and verification plan

Implement highest-priority defects and connected overview/usability improvements using existing routes, tables, permissions and components. Preserve pre-existing user edits in Request.php, NextStep.php, functions.php and untracked deployment/seed/export assets. Do not alter environment settings or configured database records, remove history, introduce external services, automate sensitive decisions or change the manual workflow rules.

Baseline: PHP 8.2.12 and MySQL 8.0.42 available through XAMPP. Existing PHPUnit suite executed successfully: 1 test, 4 assertions. Sandbox PHP file-readability and socket restrictions initially blocked it; same suite and aggregate read-only inspection succeeded outside sandbox. `cli/flow.php` mutates accounts, records and files, so must only run against a separate fixture database and isolated storage. Add focused regression tests for authorization, transactional finance/decisions, queue definitions and failure paths. Record actual results and remaining manual/browser limitations in the completion report.
